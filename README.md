# bar_scene_client

Клиентская часть многопользовательской 3D-сцены бара: React + TypeScript + Three.js (`@react-three/fiber`, `drei`), обмен данными с сервером через SignalR.

Пример работы: [t.me/koshelenok3d/35](https://t.me/koshelenok3d/35)

## Что делает

- Загружает 3D-модель бара из `public/scene_to_glb_16.glb` и рисует её: пол, стены, мебель, лампы.
- По клику по полу задаёт точку назначения, и персонаж (пока — параллелепипед) идёт к ней.
- Обходит препятствия: перед движением проверяет стены рейкастами и выбирает свободное направление.
- Отправляет свою позицию на сервер и принимает позиции других игроков, отображая их фигурки в реальном времени.
- Подключается к SignalR-хабу по WebSocket (`useSignalR.ts`, адрес по умолчанию `ws://localhost:5201/chatHub`, переопределяется через `REACT_APP_HUB_URL`).

## Комнаты

- Комната задаётся UUID в query-параметре `?room=<uuid>`. Если параметра нет (или он не UUID) — генерируется случайный UUID и записывается в адрес через `history.replaceState`, так что ссылку можно просто скопировать и отправить.
- Id участника хранится в `sessionStorage` по комнате: при перезагрузке вкладка сохраняет свой id, поэтому у остальных не остаётся «призрака» со старым id (и цвет персонажа не меняется). Новая вкладка получает отдельный id.
- Комнаты разделяются на клиенте: сервер — простой ретранслятор без групп, поэтому каждое сообщение содержит `room`, и клиенты игнорируют чужие комнаты.
- При входе клиент опрашивает комнату: рассылает `hello` со своей позицией, остальные отвечают `presence` со своей. Если комната пуста, опрос повторяется до 3 раз с интервалом 2 с (на случай, если кто-то переподключается).
- Позиция отправляется при перемещении. Каждые 30 с клиент опрашивает комнату (`hello` → `presence`), чтобы убедиться, что участники ещё на месте; пир, молчащий дольше 95 с (три пропущенных опроса), убирается из сцены.
- Последняя позиция пользователя сохраняется в IndexedDB (`roomStorage.ts`) с привязкой к id комнаты и восстанавливается при перезагрузке страницы. Записи комнат старше часа удаляются при запуске и затем каждые 10 минут.

Формат сообщений (`src/network.ts`, поле `message` в `SendMessage`):

```json
{ "v": 1, "room": "<uuid>", "kind": "hello | presence | position", "position": [x, y, z] }
{ "v": 1, "room": "<uuid>", "kind": "webrtc-offer | webrtc-answer", "to": "<client uuid>", "description": { "type": "offer", "sdp": "..." } }
{ "v": 1, "room": "<uuid>", "kind": "webrtc-ice", "to": "<client uuid>", "candidate": { "candidate": "...", "sdpMid": "0" } }
```

## Голосовой чат (WebRTC)

- Кнопка в левом верхнем углу запрашивает микрофон (`getUserMedia`) и включает голосовой чат; повторное нажатие выключает микрофон. Звук собеседников слышно только при включённом чате.
- Голос идёт напрямую между браузерами по WebRTC. Для определения внешнего адреса используются бесплатные публичные STUN-серверы (`stun.l.google.com:19302`, `stun1.l.google.com:19302`, `stun:global.stun.twilio.com:3478`); собственный TURN-сервер не нужен, пока у участников не симметричный NAT.
- Описания (`offer`/`answer`) и ICE-кандидаты передаются теми же сообщениями через существующий WebSocket-ретранслятор (`src/network.ts`, `src/useVoiceChat.ts`), с полями `room` и `to`; клиенты фильтруют чужие комнаты и адресатов.
- Для каждой пары участников создаётся одно `RTCPeerConnection`. Кто предлагает `offer`, определяется детерминированно (меньший id), а при одновременном включении микрофона конфликт разрешается по схеме «вежливого» пира (perfect negotiation), поэтому переговоры не зависят от порядка нажатий и перезагрузок.
- Громкость каждого собеседника зависит от расстояния между персонажами в реальном времени: 100 % ближе 2 единиц, затем квадратично убывает и достигает нуля на 14 единицах. Расчёт — `volumeForDistance` в `src/useVoiceChat.ts`, обновление 10 раз в секунду.
- Микрофон требует защищённого контекста: `localhost` подходит, для доступа с других устройств по IP нужен HTTPS.

## Состав

- `src/App.tsx` — сцена, освещение, комнаты, синхронизация позиций.
- `src/SceneV2.tsx` — загрузка модели, меши окружения и невидимая геометрия коллизий.
- `src/Character.tsx` — движение персонажа к цели с объездом препятствий.
- `src/Lamp.tsx` — источники света.
- `src/colors.ts` — стабильный «случайный» цвет персонажа по его id.
- `src/useSignalR.ts` — создание и обслуживание подключения к хабу, состояние подключения.
- `src/room.ts` — получение/генерация UUID комнаты и адреса.
- `src/roomStorage.ts` — IndexedDB: последняя позиция по комнате и очистка комнат старше часа.
- `src/network.ts` — протокол сообщений комнаты (позиции и WebRTC-сигналинг) и его разбор.
- `src/useVoiceChat.ts` — микрофон, WebRTC-соединения, переговоры через ретранслятор и громкость по расстоянию.
- `src/Chat.tsx` — заготовка текстового чата, в основной сцене пока не используется.

## Запуск

Клиент подключается к серверу `bar_scene_ws_server`, который должен быть запущен отдельно.
